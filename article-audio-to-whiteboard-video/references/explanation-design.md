# 从知识选择画面

先记录学习目标、已有知识、容易误解之处以及本镜视觉要增加的信息，再选形式。以下形式可组合，不要求每片全部使用，也不固定镜头数或视觉配比。

| 形式 | 主要用途 | 设计要求 |
|---|---|---|
| 图标与关系图 | 组成、层级、联系、边界 | 对象有明确名字，连接含义清楚；有方向才用箭头，包含关系用边界框 |
| 分步过程 | 操作、机制、输入输出、反馈 | 从初始状态逐步变化；重要对象保留位置，变化有原因；必要时表现检查和返工 |
| 场景插画 | 问题、目标、使用情境 | 人物或物体正在完成明确任务；动作与口播对应，避免通用“人物加电脑”装饰图 |
| 同一案例对照 | 区别、条件、优缺点 | 统一任务与比较维度；复杂对照可依次呈现，不强塞三栏小字 |
| 实物比喻 | 为抽象概念建立初步直觉 | 说明哪些特征对应、哪些不对应；后续回到实际关系，避免把比喻当机制 |
| 简化界面 | 输入、任务状态、交互、结果 | 保留讲解需要的控件，标明示意；不伪造品牌截图、真实功能或性能结果 |

## 贯穿案例

案例来自原文时延续原文；为画面新增时，标记“讲解示例”，不自动加入未经用户要求的新口播或事实。让观众能追踪同一个任务、物体或目标如何变化。

例如 Prompt、Skill、Agent 的文章可以围绕“把文章做成科普视频”展开：

- Prompt：人物交出一张写着任务要求的便签，展示一次委托。
- Skill：将经验、方法和质量标准整理成可重复使用的操作手册，再在后续任务中复用。
- Agent：围绕任务目标组织步骤，调用工具，检查输出，必要时回到前一步调整。

这只是一个解释例子，不作为所有文章的固定模板。不能画成 Prompt 消失后才出现 Skill、Skill 升级后才成为 Agent 的必经阶梯；按原文的实际关系设计。若原文本身过度绝对或有明显错误，在 editing-notes 标记并给出最小修订建议；涉及核心观点变化时保留待确认问题，不用画面悄悄修正原文。

## 每个镜头的设计问题

在 storyboard 的 purpose / composition 中回答：

1. 观众现在要理解什么？
2. 画面中谁在做什么，或者哪些对象是什么关系？
3. 随着这句话，画面发生什么有意义的变化？
4. 观众可能形成哪种误解，画面怎样避免？

如果只能回答“画面更丰富”，重新选材。若静态关系图已经完整表达，可以停稳阅读，不必添加无意义运动。

## 信息量与节奏

以最终显示尺寸和理解难度判断停留时间，不以素材数量、固定快切频率或每分钟六张图作为质量指标。过程状态保持可追踪，关键动作完成后留出理解时间；不要把复杂图放在两秒镜头里期待观众读完。

关键词尽量对应画面对象，字幕承载完整句子。避免用大段文字卡片代替解释，也避免同一句话同时成为大标题、关键词和字幕。不要为形式上的变化不断换角色、视角或物体外观。
